# Independent performer holds and submoves

Issue [#74](https://github.com/IanSzymanski/squidware/issues/74) adds an independent local-count schedule for each performer in a move. Up to 32 ordered intervals may combine straight travel, cubic travel, explicit holds and implicit gap holds. Fractional counts are supported. The show clock, tempo map, recording, metronome and other performers continue during a performer's hold. A musical fermata instead freezes the shared show count and every performer's sampled geometry.

At an arrival after the opening, select exactly one performer and choose **Edit movement timing** in the Inspector or Command palette. Existing timed paths also open this editor from **Edit performer path**. Set departure/arrival counts, then add the next interval. Straight and cubic travel expose intermediate arrival coordinates; the last travel always arrives at the next set. Cubics also expose two control points in field yards. Hold intervals inherit the preceding arrival position. Add intervals only after leaving room within the move; a newly added interval with zero duration remains an invalid preview until its counts are corrected.

Use the count slider to preview the selected performer alongside the whole cast. Solid and dashed geometry distinguish proposed and saved paths; numbered circles mark intermediate arrivals and a ring marks the selected performer. Apply validates the entire candidate and records one named undo transaction. Cancel, Escape and backdrop dismissal leave production/history unchanged. Shared focus help uses Escape first when open; dismiss help or blur its trigger before canceling the dialog. The footer remains visible while a long interval list scrolls. Other performers, endpoint pictures and musical timing are unchanged by the accepted schedule.

Before the first interval, hold the start picture. A travel starts at the preceding travel's arrival (or the start picture); each intermediate travel requires one absolute `to` point. Gaps and explicit holds keep that point. The last travel uses the destination picture without a duplicated endpoint; after it arrives, hold that endpoint through the move's remaining counts. A schedule with only holds requires identical start/end picture positions. Fully stationary travels and cubic loops are supported. Adjacent intervals share position continuously; tangent/speed continuity is not imposed. Easing runs independently within each travel window; cubic parameter timing can vary speed even with Linear timing.

Intervals require unique IDs, positive finite durations, ascending non-overlapping local counts within the move, and field-bounded finite destinations/control points. Negative/late counts, overlaps, unsorted intervals, missing intermediate destinations, duplicated final endpoints and geometry on a hold are rejected atomically. The reader never sorts or clips a contradictory schedule. All data stays subject to the 10 MiB UTF-8 file budget.

Move, performer and interval identities survive editing, undo/redo and save/reopen. Each interval's arrival identity belongs to that interval ID. Removing an interval explicitly changes the preceding-position chain in the preview; nothing changes until Apply. Endpoint picture edits retain intermediate/control points and move the derived start/final endpoints. A hold-only schedule blocks an endpoint edit that would make the two pictures different; remove its schedule first. Performer removal prunes schedules. Use default straight travel explicitly removes a custom path, restoring the whole-move straight path.

Playback/3D and the editor preview consume `sampleProject`; overlays, length and coordinate output resolve the same endpoint chain. Coordinate descriptions summarize local travel/hold windows and total travel length; arrival coordinates remain the set dots. Average step size covers the entire move including holds. Peak step size and detailed spacing/stride checks are explicitly unavailable pending #76, including the worker and reference analyzer; the worker input retains schedule geometry for that implementation. A stationary hold-only schedule prints a whole-move hold. No clearance or route-safety claim is made. The separate performer viewer is not implemented yet and must eventually use the same sampler.

[Move operations](path-operations.md) now uniformly rescale all authored intervals when counts change, reverse explicitly selected paths, and copy/paste contiguous interval ranges with reviewed destination/frame mapping. Splitting and changing a surviving detailed move's preceding set remain guarded. Changing base tempo, easing or musical timing retains the written interval counts. Field handle manipulation remains #75.

Schedules save as wire format v6. V2–v5 move data with scheduled geometry are refused rather than flattened; legacy v1 files still migrate to implicit whole-move lines. Ordinary earlier files retain their original motion and arithmetic. V6 independently supports tempo maps and recording anchors. Removing schedules restores the least required format version for the remaining curves/timing. Internal editor snapshots remain canonical schemaVersion 2.
