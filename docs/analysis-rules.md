# Production analysis rules

Issue [#44](https://github.com/IanSzymanski/squidware/issues/44) makes spacing and stride rules portable. Open **Analysis rules** in the Inspector’s Transition check section or through the Command palette. Choose production/section scope and the base or a declared direction, edit thresholds, then **Save rules**. Blank optional fields inherit. **Remove this override** clears only that scope/direction; **Restore historical defaults** restores the selected production base to 1 yd spacing and 1.25 yd/count stride. Cancel, Escape and closing the dialog discard every draft, including direction declarations. Save is one named undo transaction; undo/redo restores rules and any simultaneous declarations together. Geometry, written move timing, facing and section membership stay unchanged.

Spacing is a minimum center-to-center separation in yards. Stride is a maximum peak travel distance in yards per count; smaller limits are stricter. Both accept finite values from 0.1 to 5. For example, 1.25 yd/count is 4 steps per 5 yd. Eased moves use their peak factor of 1.5, as before. Resolution is per property: production defaults → section base → production direction → section direction. Thus a section can override spacing while inheriting stride, including within a declared direction. A pair uses the larger of its two minimum spacing values, so the stricter performer’s rule cannot be bypassed. Danger severity remains separation below half that applied minimum or peak stride above 4/3 of the applied stride limit. Flag explanations include the applied limit, units, section and declared/unknown direction.

Facing metadata is not available in this version. A field travel vector toward a sideline, midfield or any compass direction cannot establish forward, backward or sideways marching. This implementation supports **explicit designer declarations** of those three classifications for the whole incoming move. Select performers in Cast or on the field, select the destination set, open Analysis rules and use **Direction for selected performers**. Save applies this declaration with the rule edits. **Clear to unknown** removes it. Undeclared performers always use base rules, and the panel reports the unknown count even when no flags exist. Known direction overrides never silently apply to an unknown performer. These are designer declarations, not inferred facing or a new 3D pose; authored facing remains #83.

Declarations belong to an existing move and performer ID. Count/tempo edits keep them. Removed performers are pruned. Inserting, deleting or reordering sets clears declarations on any move whose endpoints change; undo restores the original metadata. Geometry edits do not infer or rewrite the designer’s classification; review declarations after reshaping travel. The declaration applies to the entire incoming move, including every independently timed travel/hold interval; no segment-facing inference is made. [Detailed checks](detailed-path-analysis.md) use conservative time-curve bounds.

The synchronous analyzer and worker use the same rule resolver. The broad phase uses the largest resolved spacing limit, then each exact pair uses its own stricter value. Worker compatibility includes saved rule definitions, declarations, resolved thresholds and section/direction labels, plus the existing geometry/timing identity. Edits clear stale flags immediately while a new result is pending; stale replies cannot become current. Geometry-only edits retain the existing incremental pair checks. No analysis preferences are read while checking an existing production.

Opening a file without rules, including migrated v1 files, uses historical defaults (1 yd and 1.25 yd/count), independently of the reader’s device. Preferences’ **New production analysis defaults** are copied into a production only when the user creates a blank/demo production. Changing those personal defaults cannot change existing project flags. Saved rules and declarations survive native save/open/recovery. These optional v2 properties are discarded by older readers that predate them; use a current reader to preserve them. The format and limits are documented in [FORMAT.md](../format/FORMAT.md).

## Design and software review

Shared guidance sections 1–5 apply. The implementation reuses Modal, HelpButton/Tooltip command metadata, native labelled inputs/selects, theme tokens, project validation and named history. The dialog identifies units, inheritance, precedence and direction-information limits next to the controls. Scope IDs remain distinct from the production-default option even when an imported section ID is literally `project`. The default 1366×768 workspace retains a 485 px field; new Inspector content scrolls within its existing panel. Dark, light and high-contrast layouts, visible focus, invalid-input messages, Cancel/Escape and 1024×720 at 150% are agent-reviewed. Required controls remain reachable through scrolling and native focus.

[Before/after screenshots and workflow results](evidence/analysis-rules/README.md) record targeted production Electron evidence. Source fixtures cover mixed sections, pair maxima, rule precedence, explicit/unknown direction, reversed travel vectors, easing, cache invalidation, reload, atomic combined save/undo, pruning/rewiring and malformed values. Schema and native file tests independently reject invalid thresholds/declarations before replacing durable data. The legacy migration oracle retains original flag identities, severity, counts and original message prefixes; explanations are newly appended. The dense 500-person correctness test has a 15-second allowance because it repeatedly materializes/deep-compares 124,750 explained flags; the production worker’s existing 15-second watchdog and cooperative cancellation remain unchanged.

`pnpm test:analysis-rules` is registered in the default desktop matrix. It tests native rule/declaration editing, Tab navigation, invalid bounds, pending-state flag clearing, real worker/reference agreement, different personal preferences, combined undo/redo, native save/reopen, Cancel/Escape, themes/enlarged access and copying defaults into a newly created production. The existing `analysis` suite covers maximum-size input, incremental edits, stale requests, same-ID loads and worker recovery. Local runs use an Xorg dummy display and temporary `--no-sandbox --disable-dev-shm-usage` launch flags; hosted Windows/macOS/Linux certification and package verification use the normal launcher. No human or physical-hardware qualification is claimed.
