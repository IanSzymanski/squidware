## Priority and effort policy

- **P0 — urgent blocker:** reserve for an evidenced critical data-loss/security/release blocker. None is currently assigned.
- **P1 — core foundations and reliability:** project compatibility, undo/recovery/save correctness, essential accessibility, measured performance and evidence needed to guide implementation.
- **P2 — planned core capability:** daily workflow improvements and roadmap features after their prerequisites. Lower estimated cost helps order similarly important ready work; it does not override correctness.
- **P3 — optional or exploratory:** specialized analysis, scripting, interchange discovery, network coordination and optional cloud collaboration until core workflows are dependable.
- Importance uses a 1–5 planning scale: 5 = foundational correctness/core access or major blocker; 4 = substantial daily/teaching benefit; 3 = useful expansion; 2 = optional/unvalidated benefit; 1 = minor polish. Direct downstream counts include open issues only.
- First stabilize #5 → #6 → #7 → #38. This explicit foundation sequence overrides a purely cost-based sort because it protects compatibility and recoverability. Other independent work and external validation may run alongside it.
- Then use a topological ordering: choose only issues whose hard prerequisites have been completed or already placed earlier in this planning queue. Among eligible items, choose P1 before P2 before P3; within a priority, prefer higher `(3 × importance + min(open direct dependents, 5)) / effort weight`, then lower issue number. S/M/L/XL effort weights are 1/2/4/8. This planning order never means that an earlier uncompleted prerequisite is actually satisfied.
- **Token effort means remaining total agent input + output tokens** for investigation, implementation, meaningful tests and review. S = 10k–30k; M = 30k–75k; L = 75k–150k; XL = 150k–300k+. These are deliberately broad, low-confidence estimates, not measured usage, model prices, deadlines or hard budgets. Human sessions, hardware access and waiting are excluded. Re-estimate after discovery or partial delivery; split XL work into reviewable slices as needed. Closed items have zero remaining effort, not a claim about historical cost.
