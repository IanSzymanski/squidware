# Show-wide problems

Open **Show-wide problems** from the timeline’s ⚠ count badge (left of the problem markers) or command search. All incoming moves are checked, including while the opening set is selected. Findings carry severity, move and destination set, absolute and move-local counts, show time in seconds, performer IDs, and an explanation of the applied spacing/stride rule. Times use the written tempo map; they are show times, independent of the attached recording’s offset.

Filter by severity, type, move, or label/ID/set/rule text; sort by count, severity, or move. The panel renders 40 findings per page with explicit totals and previous/next controls. Current-move Inspector flags now page in groups of 12. Neither list drops findings. Rows use the same names as the timeline markers below, after the severity.

## Timeline problem row

The row below the set blocks has a marker for each finding in the visible count window. Every marker is at least 24 × 24 px. Findings closer than 24 px share one marker that shows how many it holds; a long dense run splits into equal markers at least 24 px wide, so markers never overlap. A single finding shows a triangle (warning) or octagon (danger). A group shows its size in a badge: outlined for warnings, filled when it includes danger. From 1,000 findings the badge shows whole thousands rounded down (**12k**), and from 100,000 it shows **99k+**, so it never states a wrong number. Markers are named for what they hold, for example **Spacing 1.13 yd · B4, B5 · count 6** or **8 spacing problems · B8, B15, B10 and others · counts 6–8**. An abbreviated badge starts the name, which keeps the exact size, for example **12k · 12345 spacing problems · B1, B2, B3 and others · counts 40–44**, so speech input can use the visible text. Names use performer labels, whole show counts and yard values with at most three decimals; a detailed bound shows its range when the ends differ. Help adds severity, the move and its destination set, and stays inside the window.

The row is one Tab stop, like the field. Tab enters at the marker used last. Left/Right move between markers and Home/End reach the ends. Enter or Space goes to a single finding or opens a group’s list. In the list, Up/Down/Home/End move, Enter chooses and Escape returns to the group marker; in focus mode or over a tucked-panel overlay, that Escape closes only the list, and the next one exits focus mode or closes the overlay. Tab or Shift+Tab closes the list and moves on from the group marker, as from a menu button. Moving focus elsewhere, or a layout change that moves the marker (focus mode, workspace, side panel, timeline width or count window), also closes the list. A group lists its first 500 findings; a final item opens Show-wide problems for the rest. Choosing a finding uses the same review command as the panel. Focus returns to the group marker; when the review regroups the row (for example, reviewing from Cast restores the Inspector and widens the timeline), it moves to the marker now nearest the group’s first count instead of leaving the row.

Choosing a finding uses the shared `analysis.problem-review` command to stop playback, clear a rehearsal focus, seek the exact (possibly fractional) count, select the affected IDs, and return to 2D Design. Dashed paths and rings highlight that finding. Clear highlight dismisses the overlay; playback or moving to a different count hides it. Reviewing a finding does not edit positions, saved rules, file state or undo history. Finish a pending edit/preview before navigating.

## Ownership and freshness

A session-owned service queues one move at a time through the existing analysis worker; it never sends the whole production to the worker. The current move is preferred when choosing the next queued check. Reference signatures retain unaffected results. Editing a picture invalidates its incoming and outgoing moves synchronously. Timing changes invalidate later absolute counts; rule, roster and topology changes invalidate affected inputs. Undo and same-ID project replacement use the same ownership checks. Changed moves lose their flags immediately and are explicitly pending/stale until a new result arrives; completed unaffected moves remain available. Errors remain unavailable, with retry, rather than implying a passing show.

The panel displays saved project defaults and the number of section overrides; **Analysis rules…** beside them opens the rules editor. Finding text explains the applied section/direction thresholds. Existing project rules and unknown-direction behavior from #44 remain authoritative. Personal preferences do not alter an open production’s rules.

A second worker owns drag snapshots. A 120 ms leading/trailing throttle checks both adjacent moves (one at either end of the show). Every pointer change immediately hides the previous draft overlay; only results for the latest snapshot can be displayed. Draft results are explicitly marked **not committed**, draw dotted paths and endpoint rings, and never enter committed results or history. Release commits the existing single position edit and checks its affected moves. Escape, pointer cancellation, context changes and unmount discard the draft. Worker failures have an explicit unavailable state and do not run synchronous analysis on the field thread.

All results stay in session memory; unusually dense shows can have many findings. Pagination and timeline grouping bound the rendered elements, not the number of findings. The timeline groups each move’s sorted findings by track pixel once per count window, so a worker reply regroups only its own move. No project format or physical-coordinate convention changes.

## Design and validation

Shared design guidance sections 1–5 apply. The work reuses modal focus/dismissal, HelpButton/Tooltip, theme tokens, the editor store, worker lifecycle, selection and shared commands. Error rings and dashed/dotted geometry supplement status colors. Labels, counts and filters use 11–12 px text with tabular numerals where appropriate.

The 24 px marker lane follows a 14 px count ruler and 25 px set row. Without an audio lane it replaces the tracks’ 6 px bottom padding, so the timeline grows by 4 px (117 to 121 px at 1366 × 768) and the field keeps 481 px, above the 470 px target. Label heights match their tracks, including when audio is attached. Enlarged editing layouts retain their existing minimums. The analysis suite measures fixed-size layouts before showing the native window, then exercises native input and enlarged controls in the visible window. Narrow and enlarged layouts retain scrollable controls. The panel is a review dialog so the permanently visible Inspector does not grow. No new theme or persistence preference is introduced.

The `analysis` production suite owns whole-show reference comparison, complete native-keyboard pagination, filtering/search/sort, exact navigation, the one-stop timeline row (keyboard reach of every finding, group lists, 24 px targets, names and in-window help), draft pending/ready/cancel/commit, both adjacent checks, failure/retry, maximum-show coverage, rapid edits and layout captures. The existing `analysis-rules`, `timeline` and `playback` suites retain their boundaries. Source tests own signature invalidation, stale replies, count rebasing, command guards, worker restart and result grouping. Native/format suites retain file trust and compatibility.
