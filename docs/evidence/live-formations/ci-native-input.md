# Native input CI corrections

[CI run 214](https://github.com/IanSzymanski/squidware/actions/runs/41532126466) passed source verification and Windows certification, but Linux and macOS each passed 39/40 desktop suites. Linux timed out choosing “Selected dot picture” in the template-type dropdown; macOS timed out choosing the live formation's copy destination using Down/Enter. No application assertion failed before either timeout.

Parallel Linux suites previously inherited one Xvfb display. Their visible native windows could compete for focus despite separate profiles and renderer focus emulation. A local two-suite reproduction passed templates but lost text input in the competing editor. The controller now launches each parallel Linux suite under its own `xvfb-run --auto-servernum`, preserving concurrency, all suites and sequential restart phases. The fixed run used separate displays :100 and :101 under its parent display :99.

The copy test now uses acknowledged native typeahead rather than OS-dependent select-popup keys. The shared helper accepts an explicit action-completion observer for selects that unmount/reset on change. It finishes the current character's key-up acknowledgement, checks whether the copy preview opened, and stops before any remaining prefix can reach the newly focused preview. A deterministic harness test covers unmounting on the first ambiguous character and delayed key-up acknowledgement; existing numeric/Unicode, full-prefix, timeout and no-spill tests remain intact. All 16 harness tests passed.

The local targeted parallel run at implementation hash `ae1576e47959` passed live formations (78.5 s) and templates including process restart (29.8 s). Its surrounding editor regression passed the previously lost text entry and continued through endpoint drag, Apply and undo, then reached its existing 240-second process watchdog during later layout checks. This local run is not a complete editor pass; `ci-input-isolation.json` retains all three statuses. Hosted certification must confirm the full editor and remaining platform/package checks. These evidence-only files and testing documentation were added after that run.

This changes test input and process isolation only. Application geometry, UI and visual guidance are unchanged; the existing rendered review remains applicable. No checks are skipped, no failed assertion is retried, and no timeouts are increased.
