## Queued key-release correction

The [next hosted run](https://github.com/IanSzymanski/squidware/actions/runs/41166100494) passed source checks and all Windows/macOS desktop certification. Linux passed 36/37 suites; the template workflow selected the correct `snapshot` value but timed out waiting for the native key-release counter.

The counter previously counted every key release received after its listener attached. A queued Return from the preceding text edit could therefore overshoot the expected count even after the dropdown selected correctly. The [regression with the preceding helper](key-release-regression-before.txt) reproduces a timeout despite the correct value by delivering unrelated Return/Shift releases and a duplicate final release. The corrected helper matches only its own expected characters in order, case-insensitively, and ignores later duplicates. It still waits for the complete matching sequence and selected value before returning; timeout length, native input and failure behavior remain intact. Timeout diagnostics now include expected keys and the observed release count.

All **14 harness tests and 83 native tests passed**, as did the production build. The [two-suite desktop replay](ci-key-release-workflows.json) passed templates (including native library persistence/import/export), path-operations, timeline and commands using Linux CI's concurrency. This is test infrastructure only, with no application UI or project-format change. ## Acknowledged native typeahead

The [following hosted run](https://github.com/IanSzymanski/squidware/actions/runs/41243920901) exposed the remaining flaw in release counting: `1× speed` reached the correct selected value on Windows/macOS/Linux, but only the `1` release matched the expected character sequence. Linux's template dropdown also reached `snapshot` with zero matching `s` releases. Thus a correct native selection does not imply that Electron's physical `keyCode` mapping will produce a DOM keyup name matching every typed label character. The earlier queued-release regression addressed a possible counter error, but did not establish a valid native completion barrier.

The helper now sends trusted Chromium input through `Input.dispatchKeyEvent`, awaiting the acknowledgement of each key-down, text/character and key-up dispatch. Character text is explicit, including Unicode `×`. After the complete sequence is acknowledged, it separately waits for the requested selected value. It retains real native typeahead and a fresh focus session, without DOM value setters, synthetic DOM change events, OS popups, increased timeouts or retries. A timed-out input sequence stops issuing further events when its outstanding dispatch completes. All helper consumers already attach the debugger used for this native input route.

The **15 harness tests** cover repeated numeric labels, the exact `1× speed` label, missing/ambiguous options, delayed final acknowledgement when the value already matches, and a stalled dispatch that must not spill events into the next control. All **84 native tests** and the production build passed. The [complete 37-workflow run](ci-native-ack-workflows.json) passed 36 workflows at Linux CI's two-suite concurrency, including both originally failing workflows. It exposed one audio-package assertion race: waiting for an initially idle operation could return before queued Return input started the export, leaving the previous confirmation in the test variable. The failure snapshot already showed the new export running, and its generated package manifest independently confirmed the correct `reference` mode. The runner now clears the previous review, observes a fresh native confirmation and then waits for completion. The [final replay](ci-native-ack-audio-replay.json) passed audio-package, audio-clock and templates. Together these runs validate every one of the 37 ordinary desktop owners, while retaining the initial failure and each tested source identity. Chromium sandboxing remains enabled. This changes test infrastructure only; application screenshots and project-format evidence remain applicable. The report records tested source before this documentation/evidence copy; hosted cross-platform confirmation remains separate.
