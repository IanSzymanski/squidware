## Design review

[Shared design guidance](../../DESIGN_GUIDANCE.md) §§1–5 apply. The implementation reuses HelpButton/tooltips, NumberField, native selects, command dispatch, fixed formation Apply/Cancel controls, membership/copy/detachment policies, field coordinate conversion, production snapping, neighboring-path rendering and the existing analysis worker. Region vertices are square and dot controls circular; pinned rings use dashes and a labeled checkbox. Keyboard/numeric alternatives retain the field as one Tab stop rather than adding a Tab stop for every dot.

## Geometry and performance limits

Accepted points and pinned member identities persist directly; no reopen regenerates. The generator's deterministic PRNG and global 200,000-attempt budget are versioned, and insufficient-space/search failures never reduce minimum spacing or commit a subset. The bounded search is not an exact packing solver. Spacing is enforced among all reserved scatter slots, including vacancies, within 1e-8 yd. Unrelated performers are reviewed by the existing movement checks. Generation and assignment remain separate; explicit positional/roster reassignment carries pins with identities.

`benchmark.json` measures 100 runs after five warmups on this Linux/Node 24 software host, using two sets, a 40×30 yd rectangle, uniform density and 1 yd spacing. Generation p95 is **.05/.26/2.13 ms** for 2/64/500 members; geometry/project preview validation p95 is **.16/.49/6.12 ms**. These exclude rendering and asynchronous analysis. Native action-to-preview timings are separately recorded in `results.json`; they include input setup/scrolling/compositor work and are single observations, not p95 interaction guarantees. Dense worker completion is asserted before capture. Human signoff and physical-hardware qualification are not completion gates under the validation policy.
