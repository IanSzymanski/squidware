# Main-field path drawing and movement timing

This is the first incremental port for #179. Draw performer path and Edit movement timing share one session and now draw in the main field, with parameters in the existing Inspector and Apply/Cancel above its scroll area. Shared routes, Move operations, and the separate simple Edit performer path editor retain their existing presentations; #179 remains open.

The path/schedule data model, command IDs, validation messages and named undo action are unchanged. A local draft feeds both the parameter controls and the main-field geometry. Count dots and the sampled performer position use the production movement evaluator. The main field keeps its zoom, pan and orientation. Handle snapping remains an explicit option, off initially as before; numeric coordinates remain exact.

Applicable design guidance: §§1–4. Reuses the main Field2D, its viewport and theme styles, the existing Inspector layout, HelpButton/Tooltip, numeric inputs, DrawTravel fitting, movement evaluator and validated schedule.save command. The Inspector is temporarily restored if collapsed; focus mode is temporarily suspended so the parameters remain available, without saving layout changes. Unrelated edits/history are locked while a session runs. Main transport navigation ends the draft without committing it, as with formation previews. The panel's own count slider samples the draft.

Native tests cover freehand strokes and reversal, numeric anchors, handle dragging, drag rollback, screen-oriented arrow keys with a flipped field, panning, main-field zoom, fitting equivalence, hold preservation, exact before/after project fixtures, undo/redo, save/reopen, export, invalid schedules, cancel, and enlarged keyboard Apply. Brackets select field handles; arrows move them; numeric anchors complete drawing without a pointer. The field is one Tab stop. Tick coordinates preserve all samples when dense labels overlap.

Rendered review covers dark, light and high-contrast at 1366 × 768, drawing at 1024 × 768 with 150% UI scale and timing at 1024 × 720 with 150% browser zoom. Apply/Cancel stay above the scrolling parameters. The ordinary selected-performer readout is suppressed during these sessions so it cannot obscure path geometry; the panel retains numeric position/distance feedback. No modal, scrim or embedded field is present for either port.

Historical before views: [path drawing](../path-authoring/authoring-drawn-preview.png) and [movement timing](../movement-schedules/schedule-preview.png). These are preserved predecessor evidence, not newly run baseline tests.

Software-host limits: Linux x64, Electron 44.7.0, Xvfb, software rendering. Windows/macOS and package certification remain CI's responsibility. No CI result is claimed for this PR.

The field measures 513 px high at 1366 × 768 / 100%, above the approximately 470 px guidance. Drawing retains 423.5 physical pixels of field height at 1024 × 768 / 150% UI scale. Timing at 1024 × 720 / 150% browser zoom has an effective 683 × 480 viewport, so its reduced field height is expected; the field and pinned actions remain visible. This constrained window is evidence of accessible controls, not the baseline field-height target.
