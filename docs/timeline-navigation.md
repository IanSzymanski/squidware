# Timeline navigation

Issue: [#31](https://github.com/IanSzymanski/squidware/issues/31).

Use **View** at the left of the count ruler to open timeline controls. Zoom in/out keeps the visible playhead anchored; **Fit show timeline** restores the full count axis. At maximum zoom a count occupies 24 CSS pixels. The pan slider changes only the visible window; its arrow keys provide a keyboard alternative. Panning switches **Follow playhead** off, and enabling follow brings the current count back into view. Follow also handles stepping, playback and loop rewinds. The all-set picker lists each set's number, name and absolute arrival count, including all 128 sets in a maximum-length roster of sets. Choosing a set pauses playback and brings its arrival into view.

The opening picture is set 01 at show count zero. Subsequent timeline blocks describe incoming moves and select their destination sets. The ruler prefers real arrival counts, adds whole-count subdivisions when space allows, and omits labels that would collide. Short moves remain proportionally narrow at Fit; zoom or the all-set picker makes their arrivals intentional targets. Set names truncate within their blocks; hover/focus help retains the complete name and arrival.

The transport always shows opening/current destination set, local move count and absolute show count. At a boundary, `At set 03 · Move 8 / 8` describes the completed incoming move. A fraction after that boundary shows the next destination and its local fraction. Readouts use `sampleTimeline` and display up to three decimal places; they do not allocate performer geometry or round the underlying clock. A single-set show has only the opening picture and disables count stepping/playback.

The buttons beside Play and the existing comma/period commands pause and move exactly one count backward/forward from the current value, retaining fractions and clamping at zero/show end. For example, period moves 8.25 to 9.25. Shortcuts retain their existing preference bindings and do not run while typing in inputs, textareas, selects or editable content. Clicking or dragging the ruler scrubs fractionally within the visible window through the shared seek command.

Zoom, pan, follow and control expansion are session view state. They do not enter `.squid`, affect tempo/geometry, create undo transactions or mark the production dirty. Loading a different production resets the count viewport to Fit/follow. The audio lane remains hidden without an attachment and clips its existing overview to the visible count window. Measure/rehearsal content remains #51 and show-wide problem markers remain #45; the count-axis component leaves a lane insertion point for those features without inventing musical metadata.

## Review evidence

Design guidance sections 1–5 apply. This uses existing neutral theme tokens, Lucide icons, `HelpButton`/`Tooltip`, native range/select controls and the shared set/seek/count commands. Controls collapse by default to preserve field space. Expanded controls temporarily use an additional row; enlarged narrow windows use the existing scrollable workspace, and focusing controls scrolls them into view.

Before/after captures are in [evidence/timeline](evidence/timeline). The baseline is main `7b055bb`; after captures use the same deterministic 128-set production with alternating 1-, 8-, 32- and 1,024-count moves. Dark, light, high-contrast and 1024×720 at 125% are inspected. Measurements and interaction results are recorded in `review.json`. Default 1366×768 layout retains the approximately 120 px transport/timeline and 470 px field targets; the expanded view is temporary and trades field height for navigation controls.

`pnpm test:timeline` (also in the default desktop certification matrix) exercises every set with native select arrow keys, pointer ruler scrubbing, zoom, keyboard pan/follow, comma/period and transport steps, fractional/boundary readouts, text-input exclusion, playback and enlarged-theme access. Source tests cover engine boundary agreement, exact fractional steps, 128-set short/long moves and nonoverlapping labels. Navigation leaves the serialized production unchanged, so save/reopen and undo data formats are unchanged.

Local visual interaction evidence uses production Electron under Xvfb with `--no-sandbox`, because this cloud host has neither a configured setuid helper nor usable unprivileged namespaces. This is targeted UI evidence, not sandbox/platform certification. Source/native/contract checks run separately. Hosted CI must run the normal sandboxed desktop suite on Windows, macOS and Linux. The pre-existing macOS audio screenshot restoration failure recorded in [RELEASES.md](RELEASES.md) remains an explicit publication gate until exact-source certification passes. No human writer or school-hardware qualification is claimed.
