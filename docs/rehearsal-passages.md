# Rehearsal passages

Issue [#86](https://github.com/IanSzymanski/squidware/issues/86) adds annotated bookmarks and saved count ranges. Open **Rehearsal passages** with the bookmark button beside Attach audio, or search the Command palette. Name the passage, choose a bookmark or range, select its targets and optional section/performer focus, enter an annotation, then **Save passage**. Saving is one named undo action. Cancel, Escape and closing the dialog discard form changes; selecting another saved passage or New passage starts a different form draft. Go is enabled after the draft matches the saved passage.

Targets are set arrivals or local counts within a move, including fractional counts. **Use current count for start** captures the paused playhead. A bookmark starts there and continues through the show; a range stops at its end or repeats when Loop is enabled. **Go to saved passage** pauses at the start, shows the saved focus in both 2D and 3D and opens Design. Then Play, Pause, speed and Loop use the existing shared clock. Audio time remains absolute show seconds plus the project's audio offset, including ranges crossing move/tempo boundaries. Focus filters the displayed cast; it does not isolate instrument stems from the attached recording.

Section focus follows current section membership. Saved performer focus uses explicit performer IDs; choose **Replace with current selection** to update it. Empty section focus or missing performers require a new focus before use. Rehearsal focus is a read-only view and does not change positions, section assignments, written tempos, selection groups or export geometry. The passage status shows its annotation, count range and focused cast size. **Full show** clears the range/focus and pauses. Choosing a set also returns to full-show editing. Scrubbing or stepping within a range keeps it active; going outside it clears the range/focus. Loading a project clears activation; saved passage metadata survives.

Set targets follow stable set IDs, so renaming, inserting or reordering sets updates their display names and absolute counts. In-move targets retain move ID, both endpoint IDs and local count. Rewiring a move, removing a set/move, shortening a move past the target count or reversing a range marks the saved passage **Needs repair**. These references survive save/reopen and are never silently rebound. Select the passage and choose new valid targets/focus to repair it. Invalid active passages stop playback and clear focus with a message. Valid project edits also pause rehearsal while count bounds are reconciled. Undoing the edit restores metadata/targets; activation remains a session choice.

PDF/print field-chart and performer-coordinate packets append a passage page with the same resolved target labels, absolute counts, focus, annotation and repair warnings. Charts and coordinate tables retain the entire cast. CSV and the single-chart SVG keep their existing geometry-only scope. There is no standalone viewer in the current app; the future viewer remains owned by #57 and can consume these optional v2 references. Musical rehearsal marks/meter remain #51.

## Validation and design review

Shared design guidance sections 1–5 apply. The feature reuses Modal, HelpButton/Tooltip command metadata, the Lucide Bookmark icon, native labelled inputs/selects, theme tokens, named undo history, the canonical project codec and RehearsalClock. The new transport button preserves the default 485 px field height at 1366×768. Active passages add a 35 px status strip in the reviewed fixture (450 px field height), trading some field space for the explicit range/focus and Full show control; long annotations scroll within a bounded strip. The passage modal scrolls internally; at 1024×720 and 150% it uses one column and keeps Save/Cancel reachable by scrolling and keyboard focus. Supported dark/light/high-contrast output has non-color repair text and selected-item outlines.

[Before/after captures and measured results](evidence/rehearsal/README.md) record agent/software inspection. Source tests cover canonical reload, malformed/over-limit metadata, missing/rewired/shortened/reversed references, current section membership, explicit performer focus, undo/redo, 128-set navigation and escaped print references. Clock tests cover media offset, speed, silent playback and skipped-frame range stop/repeat. `pnpm test:rehearsal`, registered in the default cross-platform desktop matrix, tests native form input, invalid-count rejection, Tab/Escape, cancel, save/reopen, metadata undo, actual silent/media-backed playback and range loops, native PDF export, repair warnings and themes/enlarged layouts. The existing timeline/audio workflows cover shared navigation and clock regressions.

Local rendered interaction evidence uses production Electron on an Xorg dummy display with `--no-sandbox --disable-dev-shm-usage`, because this cloud host cannot run the normal Electron sandbox setup. These local flags are absent from the registered CI suite and shipped app. Hosted exact-source Windows/macOS/Linux certification and package verification remain separate requirements; no human or physical-hardware qualification is claimed.
