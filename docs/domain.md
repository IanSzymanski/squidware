# Drill engine contract

All geometry uses yards: x increases from the audience's left goal line (0) to the right goal line (100); y increases from the back sideline (0) to the front sideline (53⅓). Coordinate descriptions use eight steps per five yards and distinguish college and high-school hash marks. This release supports a standard 100 × 53⅓-yard football field. Imported heights within 0.001 yard of 53⅓ are normalized to exactly 160/3; other dimensions are rejected before reaching the editor or 3D renderer.

Each set contains a complete position for every performer. The first set is an opening picture with zero counts. Each subsequent set's counts, tempo, and transition describe travel **into that set**. `setStartCount(project, index)` returns that set's arrival count; subtract its duration, or use index minus one, to obtain departure count. At an exact arrival, `sampleProject` returns the arriving set with progress 1. At count zero it returns the opening set with progress 0. Timeline values clamp to the show boundaries. Tempo changes occur at each move's departure. Audio offset is applied by the playback layer, not by the count/time conversion functions.

Linear transitions interpolate coordinates directly. Ease transitions apply smoothstep, `t²(3−2t)`, to position progress; returned `progress` and `localCount` still represent elapsed counts. Every performer in a transition shares the same easing, so continuous minimum separation can be calculated in relative linear space and mapped back to elapsed time. This detects collisions between displayed frames, while avoiding false reports for geometric path intersections reached at different times.

Transition warnings use a one-yard center-to-center separation threshold; below half a yard is danger. Stride warnings begin above 1.25 yards/count (four steps per five yards), and danger above 5/3 yards/count (three steps per five yards). Eased transitions use their peak stride, 1.5 times average stride. These are geometric planning aids; they do not model instrument clearance, individual marching ability, curved travel paths, or physical acceleration limits.

Formation generation preserves performer order and returns unbounded geometry for the caller to place. Rotation is in degrees about the requested center. A single performer is placed at the center; a circle does not repeat its first point at the end. `fitFormationToField` uniformly shrinks an oversized shape around its bounding-box center, then applies only the group translation needed to fit its bounds within the field. Shapes that already fit are copied unchanged. This preserves relative geometry rather than collapsing out-of-bounds performers onto a sideline.

Translation-only transforms stop the selected group as a whole, preserving all intervals when a member reaches a field boundary. Rotation and scaling use the selection's shared centroid, then fit the complete transformed shape with the same routine; unselected positions are copied unchanged. A requested expansion or rotation may therefore be reduced by a uniform scale when the resulting group is larger than the field.

Project parsing validates schema version, bounded sizes, unique IDs within each entity collection, section references, complete positions, finite geometry within field boundaries, timing, and text lengths. It reconstructs all objects and discards unknown properties. Reserved prototype keys are forbidden as IDs. The exported `PROJECT_LIMITS` object defines 500 performers, 128 sets, 64 sections, and a 10 MiB file budget. Moves allow 1–1024 counts and tempos from 20–400 BPM. File size is measured in actual UTF-8 bytes, including multibyte characters, for both parsing and serialization. Serialization writes compact, validated JSON plus a trailing newline; unusually long IDs or notes can exhaust the byte budget before reaching the entity limits.

Roster CSV uses `label,name,section` headers. `label` is required; `name` and `section` are optional. A section may match an existing section's name or ID, case-insensitively; empty sections use the first available section. The parser accepts BOM, CRLF/LF, quoted commas/newlines, and escaped double quotes, and rejects duplicate labels, malformed quoting, inconsistent column counts, and unknown sections. Imports are all-or-nothing. The CSV export quotes every cell and prefixes potentially executable spreadsheet formulas with an apostrophe, including formulas preceded by whitespace.

`createBlankProject` starts with no performers, four sections, and one opening set. `createDemoProject` supplies 64 performers, six formations, 152 total counts, and varied tempo/easing. It is an editable demonstration, not a validated performance prescription.
